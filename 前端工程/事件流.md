
完整的流程就是：**捕获阶段（从外到内） → 到达目标元素 → 冒泡阶段（从内到外）**


### 完整的事件传播顺序：

1. **捕获阶段（从外到内）**  
    `window` → `document` → `<html>` → `<body>` → `<div>` → `<button>`  
    _（这个阶段你一般看不到，除非用 `true` 明确监听）_
    
2. **目标阶段**  
    到达 `<button>` 本身  
    _（不管 `addEventListener` 的第三个参数是 `true` 还是 `false`，目标元素上的监听器都会在这个阶段触发）_
    
3. **冒泡阶段（从内到外）**  
    `<button>` → `<div>` → `<body>` → `<html>` → `document` → `window`  
    _（这是默认的监听阶段，`addEventListener` 不写第三个参数或写 `false` 就是监听这个阶段）_



## 事件流的应用


## 事件冒泡

1. 事件委托：假如有100个子元素，点击后完成不同的逻辑，常规做法是注册100个事件，会造成资源的浪费，事件委托的就是给他们的共同父级，添加一个事件，然后同e.target知道是哪个元素，就可以解决该元素的逻辑
2. 父子同时触发事件：需要在事件中通过e.stopPropagation(),来阻止向上冒泡



## 事件捕获

走先全局后局部的逻辑，有些操作需要**父容器优先处理**，处理完再决定是否让子元素响应

例如：一个需要登录才能操作的应用。页面中有很多按钮（点赞、评论、删除等）。你希望在**捕获阶段**先检查用户是否登录。


```js
document.getElementById('app').addEventListener('click', (e) => {
    if (!isLoggedIn) {
        e.stopPropagation(); // 阻止事件继续向下传播到具体按钮
        showLoginModal();
    }
}, true); // 捕获阶段检查
```



## 没有事件流特性的事件

很多事件**默认不冒泡**，比如 `focus`、`blur`、`load`、`unload`、`scroll` 等。对于这些事件，如果想用事件委托（在父元素上统一处理），冒泡是无效的。
