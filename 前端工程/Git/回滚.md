
## 回滚本地修改的代码

1. 还没add
2. 已经add
3. 已经commit
4. 已经push

一、还没add
```shell
# 丢弃单个文件的修改
git checkout -- <filename>
# 丢弃所有未暂存的修改（危险！无法恢复）
git checkout -- .
```

二、已经add
```shell
# 从暂存区移除文件，但保留工作区修改
git reset HEAD <filename>
# 移除所有暂存文件
git reset HEAD .
```

三、已经commit
```shell
# 撤销上一次 commit，保留修改在工作区
git reset --soft HEAD~1

# 撤销上一次 commit，保留修改在暂存区
git reset --mixed HEAD~1  # 默认选项

# 撤销上一次 commit，丢弃所有修改（危险！）**常用
git reset --hard HEAD~1 ||  <commit-hash>

# 撤销特定的 commit（保留历史）**推荐
git revert <commit-hash>
```


三、已经push到远程
```shell
# 方法1：本地回滚后强制推送（会覆盖远程历史，团队协作慎用！）
git reset --hard HEAD~1 || <commit-hash>
git push -f origin <branch-name>

# 方法2：使用 revert（推荐，保留历史记录）
git revert <commit-hash>
git push origin <branch-name>

# 查看 commit 记录
git log --oneline
```


## 常用回滚

安全回滚，有历史记录
```shell
# 创建 revert commit 来撤销某个提交
git revert <commit-hash>

# 如果有冲突，解决后继续
git add .
git revert --continue

# 推送到远程
git push origin <branch-name>
```

后悔药操作
```shell
# 查看所有操作记录（包括回滚）
git reflog

# 恢复到回滚前的状态
git reset --hard HEAD@{n}
```



## 取消本次合并


仅合并
```shell
# 方法1：使用 --abort
git merge --abort

# 方法2：或者使用 reset（效果相同）
git reset --merge
```

如果已经add或者commit则按照正常流程走








## 场景

### 合并过后，无法触发新的合并，如何重新合并

一、常规回滚合并

1. 先回滚到那次合并之前
2. 执行合并
3. 再git pull

二、特殊情况，由于之前合并时就已经有问题，你这次合并，只能将2/3的东西合并进去，导致页面有问题,`就比如目前测试和分支的内容不一样，但是它们和并没有效果，比如我随便写一个字符，那么也只是那个字符的变动而已，并不会全部检查。。或者别人和你冲突很严重不是文件内容而是文件结构都改了`就是这个原因
1. 先回滚到那次合并之前
2. 直接将新分支里的全部内容，粘贴过去（不推荐这种做法）
3. 再git pull
